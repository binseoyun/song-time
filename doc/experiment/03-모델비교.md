## 5. 분석

### 5-1. 정확도가 모델 크기와 역상관 (Gemini)

가장 작고 오래되고 싼 `gemini-3.1-flash-lite`가 완벽. 이 태스크의 변별력이 **"절제"(언제 Tool을 안 쓰는가)** 에 있었고, flash-lite는 "덜 나서고 시킨 것만" 하는 성향이라 정확히 맞았다.

**과잉 호출 — flash 계열이 "친절 과잉":**

| 시나리오 (`expect: none`) | 3.6-fl | 3.7-fl | 3.5-fl-lite | 3.1-fl-lite |
|---|---|---|---|---|
| `oos-01` 신청 대행 | 5/5 | 5/5 | 0 | **0** |
| `oos-04` "꿀강이야?" | 5/5 | 4/5 | 5/5 | **0** |
| `oos-05` 취소 대행 | 4/5 | 0 | 0 | **0** |
| `oos-08` "관심과목 담아줘" | 5/5 | 5/5 | 5/5 | **0** |
| `multiturn-02` 신청대행 후속 | 5/5 | 5/5 | 0 | **0** |

`gemini-3.1-flash-lite`는 거절해야 할 때 아예 Tool을 안 부르고 "과목 코드를 알려주시면 조회해 드릴게요"로 되물음.

### 5-2. 측정 데이터의 한계·오류 예시

**(a) 답변 제외 검사 false positive** — `gemini-3.7-flash` `seats-10`. 라벨 `answer_must_not_include: ["30명", "40명", ...]`. 모델은 "'운영체제' 과목은 개설 안 됨"이라 **정확히** 답하고 유사 과목(클라우드시스템, 정원 40명)을 제시. 조잡한 부분문자열 검사가 실재 대체 과목의 "40명"을 잡음 → **할루시네이션 아님, 실질 100%.**

**(b) 답변 포함 검사가 다른 걸 측정** — `search-03`/`multiturn-04` = "심준호 교수님 수업" 질문. `search_courses`는 교수명으로 못 거른다.
- **flash 계열**: `search_courses("")` → 전체 92과목 → 스스로 "심준호=데이터베이스설계와질의" 필터 → 정답
- **flash-lite / gpt-5-mini**: `search_courses("심준호")` → `[]` → "못 찾음, 과목명으로 다시" 되물음
- **gpt-5-nano**: `search_courses("심준호")` → `search_courses("Shim Junho")`(로마자!) → `search_courses("")` → 각 분반 코드 조회 → **recursion limit 13 도달, 실패**
- `answer_must_include: ["데이터베이스설계와질의"]`는 사실상 "Tool 한계를 모델이 우회하는가"를 쟀다. flash-lite의 77.8%는 **실제 능력 차이** — 다만 오답을 안 지어내고 정직하게 되물음. Tool description에 professor 필터를 넣으면 해소(Stage 3).

**(c) 파라미터 라벨 엄격성** — `gemini-3.6/3.7-flash` 미스 3건은 전부 "라벨보다 넓은 keyword"(`keyword="데이터베이스"` vs 라벨 `"데이터베이스설계와질의"` 등). 답변은 정확. 실질 100%.

**(d) 좌석 수 드리프트 (실제론 발생 안 함)** — baseline 15:28, Gemini sweep 16:52, GPT sweep 18:57. 대조군 과목(`21003183-1`)은 세 시점 모두 "정원 60/신청 41" 동일 관측. 라벨이 교수명 위주라 무관.

**(e) 완전한 동일 조건은 아님** — baseline 단독(`--sleep 1`), sweep은 3-way 병렬(`--sleep 3`). 질문 세트·하네스·채점·시드는 동일. LLM 비결정성으로 재현 시 ±1~2%p 변동 가능.

**(f) 중복 실행 사고** — OpenAI 자동 poller와 수동 실행이 겹쳐 GPT 3종이 각각 2번 시작됨(6 컨테이너). 중복 세트를 kill하고 먼저 시작한 세트만 채택. 낭비된 API 비용 ~$0.3~0.5. 채택한 데이터는 온전(각 실행이 독립 timestamp jsonl 생성).

### 5-3. `gemini-3.7-flash` — latency가 불규칙

baseline(3.6) 대비 과잉 호출은 개선(42%→32%)이나 p95 latency **14.0초**, max **31.6초**(3.6-flash는 p95 8.0초). 과잉 fetch 74/410 최다. 스트리밍 전엔 실서비스 UX 부담.

### 5-4. GPT 계열 — "과잉 + 과소 + 느림 + 불안정" 동시

**과잉 호출**: `gpt-5-nano`(45.8%), `gpt-5-mini`(46.7%)가 **7개 중 최악** — 최악의 Gemini(3.6-flash 41.7%)보다 더 부름. GPT의 helpfulness 학습이 Tool 사용을 강하게 밈. `gpt-4o-mini`만 21.7%로 나음.

**과소 호출 (새 실패 모드)**: GPT 3종 모두 과소 호출 존재(0.7~4.8%). Gemini는 전부 0%.
- `gpt-4o-mini` `code-09` "21002144-3 교수님 성함?" → `get_course_by_code`를 **안 부르고** "특정 교수님 성함은 알 수 없습니다" 잘못 거절 (5/5). 코드가 명시됐고 Tool이 교수명을 반환하는데도.
- `gpt-5-mini` `code-03` "21102538-1 시간표 알려줘" → 마찬가지로 Tool 미호출 (4/5).
- `gpt-4o-mini` `multiturn-06` "알고리즘이랑 알고리즘입문 뭐가 달라?" → `search_courses` 없이 **자기 일반 지식으로 답** ("보통 이 과목은 심화 내용을 다루며...") — 시스템 프롬프트 "절대 추측하지 않는다" 위반. **설계가 막으려던 바로 그 할루시네이션.**

**recursion limit 루프**: `gpt-5-nano` 16건. 전부 "교수명 검색" / "search 후 결과별 fetch" 케이스에서 Tool 호출을 못 멈추고 한도(13)에 걸려 실패.

**latency**: GPT 3종 p50 11~15초, p95 21~24초 — `gemini-3.1-flash-lite`(1.7초)의 **7~9배**. GPT-5는 reasoning으로 더 느림. 채팅 UX엔 부적합.

**비용**: `gpt-4o-mini`가 1,000 turn당 $0.19로 최저(reasoning 없고 output 145 토큰/turn). `gpt-5-nano`는 reasoning 토큰(1,820 output/turn) 때문에 $0.80으로 튐. `gpt-5-mini` $1.91.

### 5-5. 수동 할루시네이션 표본 (GPT)

`gpt-4o-mini` `multiturn-06`(§5-4)이 명백한 할루시네이션 — Tool 없이 "알고리즘 과목은 보통 ~를 다룬다"를 지어냄. `code-09`도 "교수님 성함은 알 수 없다"는 사실과 다른 거절. `gpt-5-nano`/`gpt-5-mini`는 Tool을 부른 turn에서는 관측값 근거로 답했으나, `code-03` 등에서 Tool을 안 부르고 넘어간 사례 존재. **GPT 3종 모두 "정보를 Tool로만 답한다"는 시스템 프롬프트를 Gemini보다 덜 지켰다.**
