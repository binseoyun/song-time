# ADR-012: AI 챗봇 LLM 모델 선정 — `gemini-3.1-flash-lite`

- 날짜: 2026-08-27
- 상태: 결정됨
- 관련: 이슈 #78, [ADR-010](ADR-010-AI-에이전트-챗봇-설계.md) §5/§12/§14, [구현계획](../AI-에이전트-구현계획.md) Stage 0-6, [실험 03 baseline](../experiment/03-결과.md), [실험 03 모델 비교](../experiment/03-모델비교.md), Notion [보고서 04](https://app.notion.com/p/3c8b8654c5d181d2acfbec55e06255cd)·[보고서 05](https://app.notion.com/p/3c8b8654c5d181a785a2de1b14659eb8)

## 상황 (Context)

Stage 0-5에서 챗봇을 `gemini-3.6-flash`로 구현했다(ADR-010 §5는 임베딩 모델만 정했고, 채팅/Tool 호출 모델은 "그때 사용 가능한 flash"로 열려 있었다). Stage 0-6 baseline 측정(이슈 #74)에서 `gemini-3.6-flash`의 Tool 라우팅 정확도가 93.1%, 범위 밖 요청에 42% 과잉 Tool 호출임을 확인했다.

`ADR-010 §12`가 `create_agent`(LangChain)를 채택한 이유 중 하나가 "프로바이더-무관 인터페이스"였다 — LLM만 갈아끼우면 Tool 루프는 그대로 동작한다. 이 특성을 이용해, **같은 70문항 질문 세트·같은 채점·같은 하네스로 여러 모델을 실측 비교**하고 챗봇 모델을 근거 있게 선정한다.

## 검토한 대안과 트레이드오프

프로바이더 팩토리(`chat/agent.py` `build_llm(model)`)를 만들어 모델명 prefix로 LangChain 클래스를 분기했다. Claude·Grok은 저가 하한이 Gemini flash-lite / GPT nano보다 높아(claude-haiku-4-5 $1/$5, grok-4.3 $1.25~2.50/$2.50~5.00) 사용자 결정으로 이번 비교에서 제외. **Gemini 4종 + OpenAI 3종, 총 7개**를 실측했다.

전체 수치는 [실험 03 모델 비교](../experiment/03-모델비교.md) §2. 핵심만:

| 모델 | Tool 선택 | 과잉 호출 | 과소 호출 | 오류 | latency p50 | 1,000 turn 비용 | 전 rep 통과 |
|---|---|---|---|---|---|---|---|
| gemini-3.6-flash (현행) | 93.1% | 41.7% | 0% | 0 | 4.9초 | $3.26 | 64/70 |
| gemini-3.7-flash | 94.9% | 31.7% | 0% | 0 | 5.1초 (p95 14초) | $3.09 | 66/70 |
| gemini-3.5-flash-lite | 97.3% | 16.7% | 0% | 0 | 1.9초 | $0.80 | 68/70 |
| **gemini-3.1-flash-lite** | **100%** | **0%** | **0%** | **0** | **1.7초** | **$0.38** | **70/70** |
| gpt-4o-mini | 92.5% | 21.7% | 4.8% | 0 | 11.2초 | $0.19 | 61/70 |
| gpt-5-nano | 90.3% | 45.8% | 0.7% | 16 | 11.0초 | $0.80 | 61/70 |
| gpt-5-mini | 86.9% | 46.7% | 4.8% | 0 | 14.8초 | $1.91 | 58/70 |

**관찰:**

1. **정확도가 모델 크기와 역상관(Gemini).** 이 태스크의 변별력은 "맞는 Tool 고르기"(전 모델이 정보 조회 5개 카테고리 100%)가 아니라 **"언제 Tool을 쓰지 말아야 하는가"** 였고, 작고 가벼운 flash-lite가 "덜 나서는" 성향이라 정확히 맞았다. flash 계열은 거절 상황("신청해줘", "꿀강이야?")에도 `search_courses`를 부르는 "친절 과잉".

2. **GPT 3종은 "과잉 + 과소 + 느림 + 불안정"이 동시에.**
   - 과잉 호출: `gpt-5-nano`(45.8%)·`gpt-5-mini`(46.7%)가 7개 중 최악.
   - 과소 호출(새 실패 모드): GPT 3종 모두 존재. `gpt-4o-mini`는 코드가 명시된 질문(`code-09` "21002144-3 교수님 성함?")에 `get_course_by_code`를 안 부르고 "알 수 없다"고 잘못 거절(5/5). `multiturn-06`에서는 Tool 없이 자기 일반 지식으로 답 — 시스템 프롬프트 "절대 추측하지 않는다" 위반, **설계가 막으려던 할루시네이션 그 자체.**
   - `gpt-5-nano` 오류 16건 = 전부 Tool 호출 루프를 못 빠져나와 recursion limit(13) 도달.
   - latency p50 11~15초 = `gemini-3.1-flash-lite`(1.7초)의 7~9배. 채팅 UX 부적합.

3. **유일하게 `gemini-3.1-flash-lite`보다 싼 건 `gpt-4o-mini`**(1,000 turn당 $0.19 vs $0.38). 그러나 그 $0.19 절감(대화 1,000건 전체)을 위해 latency 7배·과잉/과소 호출·할루시네이션·답변 포함 57.8%(최하)를 감수해야 한다.

4. `gemini-3.1-flash-lite`의 **유일한 약점**은 "교수명으로 검색"(`search_courses`가 professor를 못 거름) 같은 Tool 한계를 우회하지 않고 "못 찾음 + 되물음"하는 것(`search-03`/`multiturn-04`, 답변 포함 검사 77.8%). flash 계열은 `search_courses("")`로 전체를 받아 스스로 필터하는 우회를 한다. **다만 flash-lite는 오답을 지어내지 않고 정직하게 되묻는다(할루시네이션 0)** — 오답이 아니라 마찰이고, Tool description에 professor 필터를 넣거나 시스템 프롬프트로 지시하면 해소된다(Stage 3-1).

## 결정과 이유

**챗봇 LLM을 `gemini-3.1-flash-lite`로 확정한다.**

- Tool 라우팅 완벽: 정확도 100%, 70/70 시나리오 전 rep 통과, 과잉 호출 0%, 과소 호출 0%, 파라미터 100%, 오류 0, 수동 할루시네이션 0.
- 가장 빠르다: p50 1.7초, p95 2.4초 (2위 `gemini-3.5-flash-lite`의 p95 3.2초, GPT의 1/9).
- 두 번째로 싸다: 1,000 turn당 $0.38 (현행 `gemini-3.6-flash`의 1/8.5). 유일하게 더 싼 `gpt-4o-mini`는 품질 격차가 커서 제외.
- 유일한 약점(교수명 검색 우회)은 Stage 3-1의 Tool description / 시스템 프롬프트 개선 범위이고, 그 자체가 오답이 아니다.

**차선은 `gemini-3.5-flash-lite`** — `3.1-flash-lite`와 거의 동급이나 과잉 호출 16.7% 잔존(`oos-04`/`oos-08`), 약간 느리고(p95 3.2초) 2배 비싸다($0.80). `3.1-flash-lite`가 문제를 일으키면 여기로.

**GPT는 이 태스크에 전부 부적합** — 어느 하나도 `gemini-3.5-flash-lite`의 종합 성능에 못 미친다.

**Claude·Grok은 측정하지 않았다** — 가격 하한이 flash-lite보다 높은데, flash-lite가 이미 이 태스크에서 만점이라 "더 비싼 모델로 더 잘할 여지"가 없다. 필요성이 생기면(RAG 결합 후 난이도 상승 등) 그때 같은 세트로 추가 측정한다.

## 결과 (정량·정성)

- **`CHAT_MODEL` 기본값을 `gemini-3.6-flash` → `gemini-3.1-flash-lite`로 변경**한다 (`chat/agent.py`, `.env.example`, `.env.docker`). 별도 PR.
- Before/After (현행 `gemini-3.6-flash` → 선정 `gemini-3.1-flash-lite`):

| 지표 | Before | After | 변화 |
|---|---|---|---|
| Tool 선택 정확도 | 93.1% | 100% | +6.9%p |
| 과잉 호출률 | 41.7% | 0% | −41.7%p |
| latency p50 | 4.9초 | 1.7초 | 1/2.9 |
| latency p95 | 8.0초 | 2.4초 | 1/3.4 |
| turn당 토큰 | 2,056 | 865 | 1/2.4 |
| 1,000 turn 비용 | $3.26 | $0.38 | 1/8.5 |

- **정성**: "가장 크고 비싼 모델이 가장 낫다"는 통념이 이 태스크(구조가 단순하고 절제가 중요한 Tool 라우팅)에서는 반대로 작동함을 실측으로 확인했다. 모델 선정을 "감"이 아니라 도메인 질문 세트 실측으로 한 사례.
- **한계**: 단일 실행(5 rep), 단일 환경. RAG 결합(Stage 1) 후 3-Tool 체제에서는 난이도가 달라지므로 같은 세트로 재측정이 필요하다. GPT는 이번 결과가 나빴으나 프롬프트/Tool description을 GPT에 맞춰 튜닝하면 달라질 수 있다 — 다만 그 튜닝 비용을 들일 이유가 flash-lite 대비 없다.
- 후속: Stage 3-1에서 Tool description(professor 필터) + 시스템 프롬프트("거절 시 조회 안 함") 개선 → `gemini-3.1-flash-lite`로 재측정해 "심준호 교수님" 마찰 해소 확인.
