# ADR-001: 팀 레포에서 개인 포트폴리오 레포로 이전 및 시크릿 정리

- 날짜: 2026-07-16
- 상태: 승인됨
- 관련: Phase 1 (안전망 구축), `doc/portfolio-roadmap.md`

## 상황 (Context)

팀 프로젝트 레포(`cloudsystem-25-2`)를 기반으로 개인 고도화 작업(Phase 1~5)을 시작하려는 시점에, 저장소 점검에서 다음 문제를 발견했다.

1. **git 히스토리에 시크릿 노출**: `.env`(커밋 `84c75b5`)와 `K8s/02-secret.yaml`(커밋 `3b3e6f0`)이 과거 커밋에 포함됨. 이후 `.gitignore`에 추가했지만 히스토리에는 그대로 남아 있어 과거 커밋에서 열람 가능.
2. **`node_modules` 전체가 추적됨**: 루트와 프론트엔드 양쪽에서 커밋되어 `.git`이 169MB까지 비대화.
3. **의미 없는 커밋 히스토리**: "last merge", "k8s save" 같은 WIP 커밋 위주라 보존 가치가 낮음.

## 검토한 대안과 트레이드오프

### 1안: 기존 레포에서 `git filter-repo`(BFG)로 히스토리 세탁
- 장점: 커밋 히스토리(기여 타임라인) 보존
- 단점: 모든 커밋 해시가 바뀌어 **force push 필요 → 협업자 전원이 재클론해야 함**. 이미 끝난 팀 프로젝트에서 조율 비용만 발생. 보존되는 히스토리도 WIP 커밋이라 가치가 낮음.

### 2안: 새 개인 레포 생성 + 현재 스냅샷으로 새 출발 (선택)
- 장점: 협업자 조율 불필요. 첫 커밋부터 깨끗한 히스토리. 팀 레포(원본)와 개인 고도화 레포의 기여 범위가 명확히 분리됨. 이후 Conventional Commits로 쌓는 히스토리 자체가 포트폴리오 자료가 됨.
- 단점: 기존 커밋 이력 미보존 → 팀 레포가 그대로 남아 있으므로 원본 이력은 참조 가능.

### 이전 방식의 재선택: `.git` 디렉토리 교체 → orphan 브랜치 (트러블슈팅)
- 최초 계획은 `.git`을 백업 디렉토리로 이름 변경 후 `git init`으로 새로 시작하는 것이었다.
- **문제 발생**: Windows에서 `.git` 디렉토리 rename이 `Permission denied`로 실패. IDE의 git 통합이 디렉토리 핸들을 점유한 상태에서는 디렉토리 이름 변경이 불가능하다(Windows는 열린 핸들이 있는 디렉토리의 rename을 거부).
- **해결**: `git checkout --orphan` 브랜치로 우회. 부모 커밋이 없는 브랜치를 만들고(`clean-main`), `git rm -r --cached`로 인덱스를 비운 뒤 `.gitignore`를 적용해 다시 스테이징. **git push는 푸시하는 ref에서 도달 가능한 객체만 전송하므로**, orphan 브랜치만 새 레포에 푸시하면 옛 히스토리(시크릿 포함)는 절대 새 레포로 올라가지 않는다. 기존 히스토리는 로컬 `.git`에 그대로 남아 자연스럽게 백업 역할을 한다.

## 결정과 이유

1. **새 개인 레포(`binseoyun/song-time`)에 orphan 브랜치 스냅샷으로 이전한다.** 협업자 조율 비용 제거 + 깨끗한 시작점 확보.
2. **첫 커밋 전 위생 검증을 필수 절차로 한다**: `git ls-files`로 `.env`, secret yaml, `node_modules`, `__pycache__`, 개인 산출물(PDF 등)이 스테이징되지 않았음을 grep으로 확인 후 커밋.
3. **`.env.example` 템플릿 3종을 커밋한다** (루트 docker용, backend용, ai-server용) — 시크릿 없이 필요한 변수 목록만 문서화.
4. **노출됐던 키는 전부 로테이션한다**: JWT_SECRET, DB 비밀번호, GEMINI_API_KEY. 히스토리를 새 레포에 안 가져가도, 팀 레포에는 여전히 남아 있으므로 "유출된 키"로 간주한다. (팀 레포가 public이면 private/archive 전환을 팀에 요청)

## 결과 (정량·정성)

- 새 레포 초기 커밋: 128개 파일 (기존 추적 파일 수 대비 node_modules 수만 개 파일 제거)
- 저장소 크기: `.git` 169MB → 새 레포는 소스만 (푸시 후 실측치 기록 예정)
- 시크릿 노출: 히스토리 포함 0건 (grep 검증 완료)
- 정성: 이후 모든 커밋이 포트폴리오 서사의 일부로 기능할 수 있는 상태 확보
